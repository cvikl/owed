Eight rules, whole cents

  
The AI asks. Code decides from PayPal's record.

  
    
    
  1. Identity. This session's order.
    2. 
    
  2. Amount. Captured less refunded, at most.
    3. 
    
  3. Owed by the record. Overcharge, duplicate, cancelled.
    4. 
    
  4. Claim against the record. Not received needs the tracker to agree.
    5. 
    
  5. Duplicates. Never twice.
    6. 
    
  6. Limits. One refund per order.
    7. 
    
  7. Velocity. Daily cap per customer.

  8. Everything else to a person, with the evidence. Open dispute: to a person.

More on the gate
Both sides ask for a refund through PayPal's own refund call. Behind Owed that call is only a request: code works out from PayPal's records and the shop's order what is owed, then runs the rules in whole cents. If the AI ends without asking, the model is asked once what the customer claimed, and if money was claimed the record settles what it proves.

For shops

  

    
Same create_refund call, routed through the gate.

    
// before: the AI's refund call goes straight to PayPal
tools.create_refund = (input) => paypalToolkit.handleToolCall(call)

// after: the same call becomes a request, and Owed pays what PayPal's records prove
tools.create_refund = (input) => owed.gate({ order, askedCents, paypal, ledger, loadRecords, rules })

    
What this is not
A real deployment needs your order records, a way to tie a conversation to a customer and an order, your own limits, a durable database for the ledger and a queue for the cases that go to your staff. This demo is a single process with the ledger in memory and has only ever run on the PayPal sandbox. The benchmark is our own test suite on a PayPal stand-in; the arena and the race test are the live sandbox evidence.
